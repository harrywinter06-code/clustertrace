- 2026-05-21 — v0.7.1: rigorous red-team pass found 3 real bugs in the Group 1 additions and fixed all. - 2026-05-22 — v0.8.0 phase-3 (c): **cluster pass/fail assertions + `clustertrace check` CLI**. New `clustertrace.assertions` module: rules are JSON blobs, four kinds supported — `success_rate_above`, `avg_latency_below`, `avg_cost_below`, `no_new_traces`. Each takes an `over_last` window in `traces` (count) or `seconds` (time). avg_cost_below skips traces with no cost data rather than counting them as zero — that would flatter clusters that never report cost. Validation rejects bad thresholds at insert time. CLI: `clustertrace assert <sig_hash> --success-rate-above 0.9 --over-last 100` (bare integer = traces; `1d` / `24h` / `60s` = time; `--no-new-traces` always uses seconds). Exactly one assertion kind per invocation enforced. `clustertrace check` evaluates every persisted rule, exits 0 if all pass, 1 if any fail; `--format json` dumps a CI-consumable payload (`{"passed": bool, "n_assertions": N, "n_failed": N, "results": [...]}`). By default, assertions on `expected-failure` clusters don't tank the exit code — pass `--include-expected-failures` to count them. 26 new tests cover every rule kind (pass/fail/vacuous-pass), validation errors, the CLI exit-code contract, JSON-format parseability, the annotation-exclusion override, and edge cases (empty assertion list exits 0, time-windowed sliding). 224/224 tests passing, ruff clean. Tagged v0.8.0.
